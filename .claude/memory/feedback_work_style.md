## Work Style Preferences

- **先说服再动手**: 用户不喜欢直接被告知做什么，喜欢先讨论"为什么做"、"值不值得做"、"意义是什么"，认可后才动手
- **要务实不要炫技**: 不要为了套概念（Agent/RAG/etc.）而上技术，要从真实痛点出发，技术为业务服务
- **小步验证**: 喜欢先把原型做出来跑通再迭代，不喜欢一开始就搞大架构
- **简历导向**: 做项目的底层动机是求职，技术选型和方案设计要考虑"能不能写到简历上"、"面试时能不能讲出东西"
- **适合短回复**: 解释性内容适度，不喜欢太长篇大论
- **纠结但清醒**: 用户会反复追问"这有什么意义"，这是好事——说明思考深入，不是盲目接受

- **理论+实操交叉学**: 不喜欢纯理论也讨厌纯搬砖，要"懂原理"和"会实操"兼顾。最佳节奏是 40% 视频 + 60% 代码交替，看几集立刻写代码，卡住了精准查，不要刷完整个系列再动手。需要视频补充时优先推荐实操导向的（LangChain/LlamaIndex 官方文档 > 实操课 > 理论课）
- **用户不喜欢全盘否定的建议**: 之前说"你收藏的视频都没用"被用户反驳——用户需要的是精准筛选，不是全盘否定。应该帮用户从已有资源中挑有价值的，而不是说都不行

**Why**: 多次对话中观察到：用户对 RAG 方案的质疑（"这些问题你也可以做啊，我做这个意义何在"）、最终因为想清楚而决定做、强调简历价值和叙事能力。当我说"视频都没用"时用户反驳"不补理论你怎么教会我写代码"——说明用户要的是精准指导而非极端建议。

**How to apply**: 给出建议时先说"为什么"，技术选型给两个方案让用户选，不要替用户做决定。用户质疑时正面回应，不要回避或转移话题。评估学习资源时，从用户已有资源出发做筛选优化，不要全盘否定。
